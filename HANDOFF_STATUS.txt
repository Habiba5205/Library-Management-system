PREVIOUS UPDATE - 2026-09-09
Service/repository cleanup, real Stripe payments, user status instead of
delete, a member-facing book catalog on the home page, and a currency fix.
- Payment/fine workflow logic that lived in Repositories (PaymentWorkflowRepository,
  OverdueFineRepository, FinePaymentRepository - all business logic, no
  interfaces, injected as concrete classes) moved to Services as
  PaymentWorkflowService, OverdueFineService, and FinePaymentService, each
  behind a proper interface (IPaymentWorkflowService, IOverdueFineService,
  IFinePaymentService). Repositories now only do data access. No behavior
  change, no new migration.
- Stripe Checkout replaces the old demo card simulator for both borrowing
  payments and fine payments. New IStripeCheckoutService/StripeCheckoutService,
  plus StripeWebhookController at /stripe/webhook (the webhook is the source
  of truth; the browser's return URL also reconciles immediately so the
  Details page updates without waiting on the webhook). Added the Stripe.net
  NuGet package and a Stripe config section - real keys go in
  `dotnet user-secrets`, never in appsettings.json:
    dotnet user-secrets set "Stripe:SecretKey" "sk_test_..."
    dotnet user-secrets set "Stripe:PublishableKey" "pk_test_..."
    dotnet user-secrets set "Stripe:WebhookSecret" "whsec_..."   (from `stripe listen`)
- Card payments are now gated on IStripeCheckoutService.IsConfigured, not on
  IsDevelopment() - Card works in any environment once Stripe keys are set,
  and fails gracefully ("Card checkout isn't available right now. Choose
  Cash instead.") if they are not.
- All money is now explicitly USD end to end. It was previously a mix of an
  EGP-labeled Stripe charge and culture-dependent ToString("C") formatting in
  views (which only ever showed "$" because of the dev machine's culture, not
  because the app enforced it). Added Extensions/MoneyExtensions.cs
  (decimal.ToUsd(), pinned to en-US) and switched every money display plus
  the Stripe Checkout currency to it.
  Note: Fine.Reason rows generated before this fix still contain the literal
  text "EGP" (stored data, not code) - run once against LibSystemMvcDb if
  that matters:
    UPDATE Fines SET Reason = 'Automatic overdue fine ($5 per day)'
    WHERE Reason LIKE '%EGP%';
- Admin no longer deletes users. UserController.Delete/DeleteConfirmed
  replaced with Deactivate (confirmation page, choose Active/Deactivated/
  Suspended) and a one-click Reactivate. IUserService.DeleteAsync replaced
  with SetStatusAsync(id, status). An admin cannot change their own status
  (guards against self-lockout). Login already rejected non-Active users
  before this change (IUserRepository.GetActiveByUsernameOrEmailAsync), so
  this was mostly wiring the existing User.Status field into the UI instead
  of hard deletes - no migration needed, the column already existed.
- Member home page (Views/Home/Index.cshtml) now lists the full book catalog
  with an Available/Borrowed-style status badge and a direct Borrow button,
  via a new DashboardViewModel.Books list (populated for Members only - Admin
  and Manager dashboards are unchanged).
- Tested locally end to end: repo/service refactor, Stripe test-mode checkout
  (borrowing + fine payment, both cash and card), user status changes
  (deactivate/suspend/reactivate), member book catalog, USD formatting.
  All confirmed working.
- Correction to the "Authentication/login status" note further below: the
  old line said Admin "cannot create, edit, delete" - that was never accurate
  for Users specifically (UserController's Create/Edit are, and always were,
  [Authorize(Roles = "Admin")]). Updated in place rather than left
  contradictory.

FINE PAYMENT AND RETURN UPDATE
- Supersedes the earlier pay-after-return rule: unpaid fines now block returns.
- Members select Cash or Card for their own fines.
- Cash confirmation records receipt of cash and book; demo Card success settles
  automatically. Settling the last fine also returns the book atomically.
- Fine amount is checked again at completion; increases require member
  confirmation. Failed/cancelled card attempts leave the fine unpaid.
- Cash fine payment has no reservation expiry.
- Fine edit and delete routes removed to prevent payment bypass.
- AddFinePayments migration required.

AUTOMATIC FINES - 2026-09-07
- Manual fine creation and Add Fine shortcuts have been removed. Existing
  manual fine records are preserved.
- 5 EGP per overdue calendar day, starting the day after the due date.
- One automatic fine per borrowing; daily amount updates stop on actual return.
- Active overdue loans and early-return requests are checked every minute and
  before requests. Downtime is caught up on the next check.
- Manual fines are preserved; old completed loans are not retroactively charged.
- Managers can mark automatic fines Paid after return; amounts and links are
  protected and automatic fines cannot be deleted.
- Added AddAutomaticOverdueFines migration.
- Integration checks include rate, due-date boundary, catch-up, frozen returned
  amounts, duplicate prevention, and manager payment restrictions.

Authentication/login status:
- Cookie authentication is implemented.
- Login and logout are implemented through AccountController.
- Demo accounts are created automatically when the app starts if they do not exist:
  - admin / Admin@123
  - manager / Manager@123
  - member / Member@123
- Admin manages Users (create, edit, and change status to Active/Deactivated/
