30. Added UserFormViewModel (ViewModels folder) with a plaintext Password

32. Password is required on Create; optional on Edit (blank = keep current
    password).
33. User delete is blocked if the user has borrowing history

37. Added BorrowingFormViewModel for selecting an available book, selecting

38. Built matching Razor views under Views/Borrowing.
39. Borrowing Create blocks unavailable books and only accepts users with the

40. Borrowing Create sets the borrowing status to Borrowed, calculates DueDate,

Important note:
The API specification was converted into an MVC project direction. We are not building API endpoints right now. The next work should use Controllers and Razor Views, not Web API controllers.

Known gaps / things to watch:
- No authentication/login exists yet. Password hashing is in place, but
  there's no login page, session, or cookie auth wired up - a user's
  password is stored securely but nothing checks it against anything yet.
  This may be needed if the instructor requires login, per the original
  spec's "optional bonus" auth requirement.
- Plain `dotnet build` may ask for a project/solution choice because the
  folder now contains both a project file and a solution file. Use
  `dotnet build Lib_System.csproj`.
